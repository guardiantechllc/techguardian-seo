# Tech Guardian — EspoCRM Repair Shop Setup

A production-ready, self-hosted CRM for a device repair business,
built on EspoCRM 8 with Docker. Custom **RepairTicket** entity with
a 7-stage pipeline, auto-calculated pricing, auto-generated ticket
IDs, workflow automations, and a revenue dashboard.

---

## What you get

| Feature | How |
| --- | --- |
| **7-stage pipeline** | New Lead → Diagnosed → Awaiting Parts → In Progress → Ready for Pickup → Completed → No Fix. Kanban drag-and-drop included. |
| **Auto ticket IDs** | TG-0001, TG-0002, ... via a PHP hook. Sequential, zero config. |
| **Auto-calculated financials** | `totalCost = partsCost + laborCost`, `profit = quotedPrice - totalCost` via a before-save formula. |
| **48-hour stale flag** | Scheduled workflow flags tickets with no update in 48h. Auto-clears when you touch them. |
| **SMS on "Ready for Pickup"** | Webhook fires when status changes — plug in Twilio, Vonage, or any SMS provider. |
| **Revenue logging** | `completedAt` auto-stamps, follow-up Task auto-created 7 days out. |
| **Dashboard** | 4 KPIs (Revenue, Profit, Jobs, Avg Profit) + active repairs list + daily trend chart. |
| **Google Sheets sync** | One-way mirror via a Python script on cron. No paid integrations. |
| **Docker deployment** | One `docker compose up -d` and you're running. |

## Quick start (macOS / Linux)

```bash
# 1. Navigate to the setup directory
cd espocrm_setup

# 2. Create your .env
cp .env.example .env
open -e .env  # or: nano .env
# At minimum, change the passwords from the defaults.

# 3. Launch EspoCRM + MySQL + daemon
docker compose up -d

# 4. Wait ~30 seconds for first-time initialization, then install
#    the RepairTicket entity
./install.sh

# 5. Open in browser
open http://localhost:8080
# Login: admin / (whatever you set in .env)
```

After login:
- **Repair Tickets** appears in the top nav
- Click **Repair Tickets** → **Kanban** view toggle (top right) to see the pipeline
- Create a test ticket — it should get TG-0001 automatically

## Post-install setup (one-time, ~25 minutes)

After `install.sh` runs successfully:

### Step 1: Build the 4 workflow automations (~15 min)
Follow **`docs/WORKFLOWS.md`** — covers:
1. Auto-assign "New Lead" on creation
2. Flag stale tickets (48h scheduled check)
3. SMS/email on "Ready for Pickup"
4. Revenue logging + 7-day follow-up Task on "Completed"

### Step 2: Build the dashboard (~10 min)
Follow **`docs/DASHBOARD.md`** — covers:
- 4 KPI report dashlets (Revenue, Profit, Jobs, Avg Profit)
- Active Repairs record list
- Daily Revenue Trend chart
- Kanban board setup

### Step 3: (Optional) Google Sheets sync
Follow **`docs/GOOGLE_SHEETS.md`** — covers:
- Creating an API User in EspoCRM
- Running `scripts/sheets_sync.py` on cron

## Updating the customization

If you modify any file under `custom/`, re-deploy with:

```bash
./install.sh
```

The script copies files, fixes permissions, and rebuilds the cache.
No downtime — EspoCRM picks up changes immediately.

## How this fits with the lead_system

The Python lead monitor (`lead_system/`) finds leads and writes them
to Airtable/Sheets. EspoCRM is where you manage the actual repair
workflow after a lead converts to a job.

The bridge: when a lead in `lead_system` gets status `booked`, you
(or an n8n workflow) creates a RepairTicket in EspoCRM via its REST
API:

```bash
curl -X POST http://localhost:8080/api/v1/RepairTicket \
  -H "X-Api-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "PS5 HDMI port — no display",
    "customerName": "Jane Doe",
    "phoneNumber": "816-555-0101",
    "deviceType": "PS5",
    "issueDescription": "HDMI port bent, no signal on any TV",
    "leadSource": "Yelp"
  }'
```

The ticket gets TG-#### automatically, starts at "New Lead" status,
and enters your Kanban pipeline.

## Troubleshooting

- **"Repair Tickets" tab missing** → Admin → Rebuild (top right).
  If still missing, check that `install.sh` ran without errors.
- **Ticket ID is empty** → The PHP hook didn't fire. Check that
  `custom/Espo/Custom/Hooks/RepairTicket/TicketId.php` exists in the
  container: `docker exec techguardian-crm ls custom/Espo/Custom/Hooks/RepairTicket/`
- **Profit shows $0** → The formula runs on save. Open and re-save
  the ticket to trigger it, or check that quotedPrice is filled in.
- **Kanban board is empty** → Make sure you're viewing "All" records,
  not just "My". Click the filter dropdown in the top left.
- **Docker won't start** → `docker compose logs espocrm` to see the
  error. Common cause: port 8080 already in use (`lsof -i :8080`).
